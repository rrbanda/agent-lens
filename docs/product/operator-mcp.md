# Operator guide: official MLflow MCP

Agent Lens Hermes talks **only** to upstream official MLflow MCP
(`mlflow mcp run`), typically exposed in-cluster as Service **`mlflow-mcp`**.

This repository does **not** deploy that MCP server.

## Expected topology

| Piece | Typical location |
|-------|------------------|
| MLflow tracking | `redhat-ods-applications`, port 8443 |
| Official MCP | `redhat-ods-applications`, Service `mlflow-mcp`, port **8080**, path `/mcp` |
| Agent Lens (production) | OpenShell **Sandbox** in namespace `openshell`, Route `agent-lens`, port 9119 |
| Inference | LlamaStack (`llamastack` ns, port 8321) via `OPENAI_BASE_URL` env var |
| Image build | ImageStream/BuildConfig in namespace `agent-lens` (`python:3.13-slim` base) |
| OpenShell Gateway | `openshell` ns, StatefulSet, port 8080, mTLS enabled |

Default Hermes URL ([`agent-lens/config.yaml`](../agent-lens/config.yaml)):

```text
http://mlflow-mcp.redhat-ods-applications.svc.cluster.local:8080/mcp
```

Env `MLFLOW_MCP_URL` on the Sandbox overrides the ConfigMap URL at startup
(`agent-lens/deploy/openshell/startup.sh`).

## Deploy (OpenShell)

No local podman/docker is required. All deps are baked into the image at build time
(runtime pip is blocked by the OpenShell supervisor's Landlock sandbox).

```bash
# 1. Platform prereqs (see agent-lens/README.md for full setup):
#    - Agent Sandbox Controller installed
#    - OpenShell gateway deployed with mTLS (helm install ... --version 0.0.85)
#    - SCC binding: oc adm policy add-scc-to-user privileged -z openshell-sandbox -n openshell
#    - mTLS client certs: secret openshell-client-tls (auto-generated by Helm)

# 2. Auth secret (dashboard + API key)
make secret-openshell

# 3. Build image in-cluster (python:3.13-slim base, ~60s)
make build-agent

# 4. Apply Sandbox + Service + Route + NetworkPolicy
make deploy-openshell

# 5. Verify
make status
```

See [enterprise-readiness.md](enterprise-readiness.md) for the full production checklist.

## Preflight checklist

```bash
# 1. MCP pod ready
oc get pods -l app=mlflow-mcp -n redhat-ods-applications

# 2. Service exists
oc get svc mlflow-mcp -n redhat-ods-applications

# 3. Agent Lens status helper
make status

# 4. Optional: allowlist vs live tools/list
MCP_URL=http://mlflow-mcp.redhat-ods-applications.svc.cluster.local:8080/mcp \
  ./scripts/check_mcp_contract.sh
```

## Recommended MCP env (platform-owned)

| Variable | Guidance |
|----------|----------|
| `MLFLOW_TRACKING_URI` | In-cluster MLflow HTTPS URL |
| `MLFLOW_TRACKING_TOKEN` | Usually projected SA token |
| `MLFLOW_MCP_TOOLS` | Prefer GenAI tools; `all` is fine for pilots |
| `MLFLOW_WORKSPACE` | Match your MLflow workspace (often `default`) |
| TLS bundles | `REQUESTS_CA_BUNDLE` / `SSL_CERT_FILE` for cluster CA |

Exact manifests are owned by the MLflow operator or your deployment stack — not this repo.

## Network

Sandbox pods in `openshell` must:

1. Resolve cluster DNS (NetworkPolicy must allow **UDP/TCP 5353** to `openshift-dns` — OpenShift CoreDNS pod port)
2. Reach `mlflow-mcp:8080` in `redhat-ods-applications`
3. Reach LlamaStack `:8321` and OpenShell gateway `:8080`

Manifest: [`agent-lens/deploy/openshell/network-policies.yaml`](../agent-lens/deploy/openshell/network-policies.yaml).

## Common failures

| Symptom | Check |
|---------|-------|
| Connection refused / timeout | MCP pod, Service, NetworkPolicy, wrong URL in ConfigMap |
| Temporary failure in name resolution | NetPol DNS — allow **5353** to `openshift-dns`, not only port 53 |
| Tools missing in Hermes | `tools.include` in `config.yaml` vs upstream names (`./scripts/check_mcp_contract.sh`) |
| Annotate/eval fails | Judge/LLM config on MLflow side; MCP logs |
| Dashboard INACTIVE for all agents | No traces yet — see [first-trace.md](first-trace.md) |
| Sandbox CrashLoop / Missing SA | `openshell-sandbox` SA + SCC binding + `openshell-client-tls` in `openshell` |
